# 建模、材质与布光

## 建模确认（出分镜前必须过）

1. **从资料读结构**：照片、拆机图、规格书是依据。逐项读出部件、数量、排布、分组、标记、尺寸。数量能数就放大照片数，数不清就写「约」，并说明是怎么数的。
2. **列结构清单给用户看**。写法举例：
   - 吸顶灯：「4 条灯条顺长边排，每条分 2 段，每段约 24 颗，3 颗一组焊在小板上；两种色温的灯珠交替；驱动在中间」；
   - 净化器：「三层滤网从外到内依次排列；风机在底部；两侧进风、顶部出风」。
3. **渲一张模型静帧**，和清单一起交给用户确认。
4. 用户指出的偏差（比如「这个部件在照片里是歪的，做的时候摆正」）直接按用户说的改，不要照搬照片里的偶然状态。

## 照实拍核对建模

用户给了实拍照片、要求「1:1 还原」时，不要只在片子的镜头里凭感觉调：

1. **做一个核对用的版本**：一两帧、固定机位，机位角度和照片一样（侧面斜拍、正面各一个）。照片多是长焦拍的，透视弱，核对机位也用窄视角（十几度）、拉远距离，否则近大远小会让比例判断失真。
2. **从照片量比例，而不是量绝对尺寸**：以一个已知尺寸的部件为单位（比如透镜半径 R），读出高度、边沿宽度、内部结构和间距的比值。斜拍时先用底部圆形边沿的椭圆扁度估仰角（短轴 / 长轴 ≈ sin 仰角），再把看到的高度折算回真实高度。
3. **左实拍、右模型并排拼图**，逐项对：外形比例、边沿、内部结构、材质（透明 / 磨砂 / 反光）、发光的位置和形状。
4. **照片量出来的数和用户的判断冲突时，以用户为准**。照片透视反推有误差；用户说「太高」「太矮」时，取两次反馈之间的值，再出对比图确认。
5. 核对机位看到的模型问题，在片子里也会存在；但改完要回到片子的关键帧再看一遍，核对机位和实际镜头的光照不同。

## 建模手法

- **单位用米**，按真实尺寸建；关键的小部件可以适度放大，保证看得清（比如把几毫米的贴片元件放大 1.5–2 倍）。
- **圆角板件**：用圆角矩形 `Shape` 加 `ExtrudeGeometry`（带倒角）；小方块用 `RoundedBoxGeometry`。
- **朝下的面**：形状在 XY 平面，`rotation.x = +π/2` 以后正面朝下，形状的 y 对应世界的 z。
- **导线**：`CatmullRomCurve3` 加 `TubeGeometry`，沿着边缘和底盘布线。悬在空中横跨间隙的导线看着像棍子。
- **重复部件**（几百颗灯珠、按键、电芯）：几何体共用一份，材质按需每个一份，方便单独控制；数量在几百这个级别，直接用多个 mesh 就够，不必上 InstancedMesh。
- **分层装配**：会一起移动的部件（比如电路板、电源和它们之间的导线）放进同一个 group，拆解时整体偏移，连接关系不会断。

## 程序化贴图（Canvas 2D）

- 用 Canvas 画出走线、焊盘、丝印、铭牌、地板、装饰画，转成 `CanvasTexture`，设 `colorSpace = SRGBColorSpace`，`anisotropy` 调高。
- `ShapeGeometry` 的 UV 等于形状坐标（米）：贴整张图时设 `repeat = 1/尺寸`、`offset = 0.5`。
- **铭牌、规格这类文字直接按真实参数画**，近景能读出来，本身就是科普信息。
- **微距镜头**：整块贴图的分辨率不够，在主角部件周围叠一张高分辨率补丁，边缘用渐变 alpha 羽化，再加 `polygonOffset` 防止闪烁。补丁和底图用同一个绘制函数，内容才对得上。补丁是透明且不写深度的，要设更小的 `renderOrder` 先画，否则会盖掉它上方后画的透镜、光晕。
- 噪点、颗粒这类随机元素用固定种子的伪随机函数生成。

## 布光配方

| 镜头 | 灯光 |
|---|---|
| 拆解、结构展示 | 一盏方向光从斜下方打主光，加半球光补暗部 |
| 微距 | 一盏聚光贴着目标打低角度侧光，强度 = 目标照度 × 距离²；发光体自己再加一盏很弱的点光，照亮周围 |
| 多个发光体整体点亮 | 发光面前方加一盏弱点光，模拟所有发光体的溢光，强度跟点亮数量走 |
| 使用场景（室内） | 主光源位置一盏点光（开阴影），加半球光和一盏低处补光模拟地面反射；房间变大时补光按面积比例减弱 |

- 所有灯光强度都按帧号插值，镜头之间交接时淡入淡出。
- 场景里同时有「产品棚拍」和「使用场景」时，给所有场景材质的颜色统一乘一个「场景亮度」系数。系数为 0 时场景全黑，棚拍光就照不亮场景；转场时再把系数推上来。
- 镜头运动会改变灯光入射角，照度可能跳变。抽帧发现亮度跳时，在这一段单独把主光压一下。

## 发光与辉光

- 发光体用 `emissive`，强度大于 1，并设 `toneMapped: false`，后期辉光才会被触发。
- 微距时发光体占满画面，强度给低一些；拉远后发光体变小，需要更高的强度才撑得起辉光。强度按镜头远近插值。
- 透明材质（透镜、玻璃）的自发光会被不透明度缩放，调大就变成白色实心。这类材质的自发光要很低，光集中在内部的发光芯上。
- 有多种发光体时（比如两种色温、指示灯的不同颜色），分别用各自的发光颜色，熄灭时的底色也要区分。熄灭态的颜色不能太深，否则看着脏。

## 透明透镜配方（灯珠透镜、玻璃罩这类）

实物透镜本身几乎看不见，看得见的是光：灯珠的光被拱顶轮廓和底部边沿兜住，轮廓一圈发亮，拱顶接边沿处一道最亮的细线，内腔里一条亮芯。按这个思路分层做：

| 层 | 做法 |
|---|---|
| 外形 | `LatheGeometry` 按剖面画：底部薄边沿 → 竖直短边 → 球冠；比例照实拍量（见上面「照实拍核对建模」） |
| 本体 | `MeshPhysicalMaterial({transmission: 1, ior: 1.49, thickness, roughness: 0.03, clearcoat: 1, depthWrite: false})`，自发光极低 |
| 轮廓光 | 同一个几何体再叠一层加法混合的 `ShaderMaterial`：`pow(1 - abs(dot(N, V)), 3)` 的菲涅尔项，加一条以「边沿高度」为中心的高斯亮带；亮度跟灯珠点亮程度走，未点亮时留一点底亮 |
| 内腔 | 子弹头形的小 Lathe，同样材质；叠一层更弱的轮廓光 |
| 亮芯 | 内腔里一个细长的椭球，加法混合、颜色接近白、强度大于 1 触发辉光；位置要高过灯珠本体，否则侧面看被挡住 |

- 不要用「白色 + 低不透明度」：在亮底上像一层奶白色的皮，在黑底上像灰板。
- 透镜、轮廓光、亮芯都不写深度，和其他透明贴片之间要用 `renderOrder` 理顺先后。
- 几百颗透镜每颗一份材质（方便单独控制亮度）没有问题；`transmission` 每帧多一次场景渲染，整体可接受。

## 拆解爆炸图

- 沿一个轴拉开，层间距要足够大（几十厘米级），镜头仰角压低（约 25°），各层才不会在画面上互相遮挡。
- 不要用半透明表现「看进去」：黑底上的半透明物体像一块深灰色的板。
- 标注根据锚点在画面左半边还是右半边，自动决定引线往左还是往右；每个标注至少停留 2 秒。
- 拆开和装回都要给时间，装回的同时可以开始下一个镜头的运镜。

## 使用场景

以室内为例（厨房、车内、户外同理）：

- 前墙去掉，镜头从外面看进去；地面、顶面、侧墙往镜头方向延伸到画面外，画面边缘就不会露出黑边。
- 要演示面积变化时，墙、地板、家具都相对房间边界定位；地板贴图的 repeat 跟着尺寸变，木纹才不会被拉伸。
- 加法混合的地面光效要用 `clippingPlanes` 限制在地板范围内。

## 质感升级阶梯（只用 Three.js）

按投入产出比从高到低排列，每项都标了实测结论。实测场景是起步模板里的小产品（白色塑料加贴片发光体），换到大场景或几百个透明体时，速度要重新确认。

| 顺序 | 手法 | 实测结论 |
|---|---|---|
| 1 | **棚拍环境反射**：Three.js 自带的 `RoomEnvironment` 经 `PMREMGenerator` 生成 `scene.environment` | ✓ **提升最大**：白色塑料从灰色变成真白，彩色材质的颜色也回来了。代价是整个画面被提亮，暗调气氛会变淡，开了以后要调低主光；`environmentIntensity` 从 0.2–0.4 开始试。不需要下载任何文件。起步模板里改 `ENV_INTENSITY` 就能打开。 |
| 2 | **真折射**：透镜、玻璃、透明外壳用 `MeshPhysicalMaterial({transmission: 1, ior, thickness, roughness: ≈0.04})` | ✓ **效果明显**：透镜会真实地放大、扭曲下面的部件，并带高光，和手动后期管线、辉光一起用没有问题。折射率按材料设（PMMA 约 1.49，玻璃约 1.5）。 |
| 3 | **环境光遮蔽**：N8AO 的 `N8AOPostPass`，加在 `RenderPass` 后面 | ✓ **能用，效果轻微**：部件和底板的接触处多一点暗角。`aoRadius` 用世界单位（米），要按场景尺度设，默认值是给几米大的场景用的；`gammaCorrection` 设为 false（后面的管线会处理）。需要单独 `npm i n8ao`，它没有类型声明，要自己加一行 `declare module 'n8ao';`。 |
| 4 | **超采样**：渲染时加 `--scale=2` 输出 4K，需要 1080p 就再用 ffmpeg 缩小 | ✓ **能用**：输出是真 4K，后期管线也跟着按 4K 渲染。缩回 1080p 后边缘更干净、噪点更少，但已经开了 4 倍抗锯齿时差别不大，渲染的像素量却是 4 倍。**适合要交 4K 的场合**，单为 1080p 画质不划算。 |
| 5 | **运动模糊**：Remotion 的 `CameraMotionBlur` 套在 3D 画布外面 | ✗ **不推荐**：几乎看不到拖影，背景反而出现一圈圈色带，构图还会往前偏一点。原因是它把整个画布复制多层半透明叠加，每层都带背景和暗角。真要运动模糊，需要在 Three.js 里自己做子帧累积，还没实现。 |
| 6 | **材质细节**：程序化生成法线、粗糙度贴图；或从免费素材站下载照片级贴图 | 未实测。下载素材前先问用户。 |
| 7 | **调色 LUT**：postprocessing 的 `LUT3DEffect` | 未实测，需要 LUT 文件。 |
| 8 | **路径追踪**：`three-gpu-pathtracer` | 未实测。比实时渲染慢几个数量级，只考虑用在一两个关键镜头上。 |

**比较方法**：同一帧分别渲「开」和「关」两张，裁出细节区域放大对比。发光体点亮时会盖住差别，比较反射、遮蔽、折射要选发光体还没亮的帧。

# 分镜与科普表达

## 前置：建模已确认

分镜写在建模确认之后。结构没确认就写分镜，镜头会建立在错误的部件、数量或排布上，后面要整段返工。

## 分镜表

交给用户确认的分镜表固定四列，外加编号和时长：

| # | 时长 | 口播 | 要讲明白什么 | 画面 |
|---|---|---|---|---|
| 1 | 0–6s | 原口播 / **新增**口播 | 一句话的知识点 | 镜头、运动、图形、标注 |

- **口播列**：区分「原口播」和「新增」。新增口播是草稿，由用户或写脚本的人定稿；定稿前做成字幕。
- **要讲明白什么列**：每镜只讲一件事。一镜讲两件事，就拆成两镜。
- **画面列**：写清镜头怎么动、用什么图形讲、出哪些关键词，不写形容词堆砌。

## 时长

- **有配音就用配音锁节奏**，见 `audio-sync.md`：镜头卡在句子边界上，不靠估算。
- **没有配音**时，中文口播按每秒 4–5 个字估，每镜再加 0.5–1 秒的呼吸。`scripts/vo_timeline.mjs --text` 可以直接按字数算出每句的起止时间。
- 用户给的口播太短、讲不清原理时，提出放宽总时长并补口播，作为选项让用户选，不要擅自加长。
- 所有镜头的起止帧集中写在 `timeline.ts`，并尽量引用配音时间点；配音一换，只需要重新生成时间点文件。

## 科普图形手法

能用图形讲的就不用大段文字。下面按「要讲的道理」分类，不限产品。标 ✓ 的手法已经在实际项目里做过，效果可靠；其余是同一套写法的延伸，第一次用时先单镜试。

| 要讲的 | 手法 | 例子 |
|---|---|---|
| 内部有什么 ✓ | 拆解爆炸图：沿一个轴拉开各层，引线标注部件名和一句作用 | 灯具的灯罩、灯条、驱动、底盘；净化器的滤网各层；耳机的腔体和单元 |
| 东西怎么流动 ✓ | 镜头跟着流动的方向平移，路径上做流动光；输入、输出各配一个状态面板 | 电流（交流 → 直流）；净化器的气流（脏空气 → 干净空气）；热水器的水路 |
| 为什么要取舍 ✓ | 指针或滑块推过最佳点，两根柱子显示收益和代价此消彼长，再回到平衡点 | 功率与发热；风量与噪音；续航与重量 |
| 热、力、能量往哪走 ✓ | 分层示意，箭头一层层往外流 | 散热路径；受力传导；电池能量分配 |
| 数量或规格怎么来 ✓ | 分级后拉，逐级点亮或高亮，算式一项项拼出来 | 24 颗 × 2 段 × 4 条 = 192 颗；电芯串并联数；滤网层数 |
| 原理为什么成立 ✓ | 2D 剖面图配一条曲线，分步变化 | 光：尖峰 → 平线（不刺眼）；声：频响曲线变平；过滤：颗粒数随层数下降 |
| 适用范围 ✓ | 场景尺寸或条件可调，公式和读数实时变化，配一条标准值参考线 | 照明面积与照度；净化器适用面积与 CADR；充电器功率与充满时间 |
| 前后对比 ✓ | 并排两个小图：同条件下的两种方案 | 少颗大功率 vs 多颗分摊；单层 vs 多层滤网 |

- 每种手法都要配真实数据或明确的定性表达，参考「事实核对」一节。
- 2D 示意图叠在 3D 上时，把 3D 背景压到约 90% 的黑，否则背后的物体轮廓会干扰阅读。
- 字幕只出关键词、算式和结论，完整句子交给口播。

## 静帧分镜（分镜确认关交这个）

分镜确认时不要只交文字表格。每个镜头先摆好关键姿态，渲 1–2 张静帧，和表格一起交：

1. 只做每个镜头的**关键姿态**：机位、出现哪些部件、标注和面板的位置（文字可以先用占位），不做转场和动画细节。
2. 用 `scripts/stills.mjs --html` 渲出这些帧，会生成一个带帧号和时间码的图册页面 `index.html`。
3. 把分镜表和图册一起交给用户。用户在这一步指出构图、信息密度、标注位置的问题，比看到成片再改便宜得多。
4. 静帧分镜确认后，再补转场、动画和细节。

## 事实核对

画面上出现的每个数字，交付时都要说清出处：

- **实物资料**：铭牌、规格书、检测报告、包装，以照片或文件为准。
- **估算**：写出公式和假设，比如「照度 = 光通量 × 利用系数 ÷ 面积，利用系数按 0.5 估算」，并在画面角落用小字注明。
- **推断**：比如由电源的额定输出，反推单个部件实际能跑到的功率。这类推断要单独告诉用户，请品牌方确认；画面上只出能确认的部分。
- **标准引用**：国标、行标的条文和数值要请用户核对原文后再定稿。
- **数据矛盾时**（比如「数量 × 单件参数」远超总参数），先指出来，不要替用户圆。常见矛盾见 `kickoff.md`。

## 字幕规则

- 新增口播在定稿前做成字幕，放画面下方，带半透明底，避开标注面板。
- 原口播由剪辑统一加字幕，动画里不重复。

## 与实拍衔接

按衔接的紧密程度分三档，先跟用户确认用哪一档：

1. **首尾帧淡化**：实拍定格和动画首尾帧交叉淡化 10–15 帧。Remotion 可以把视频文件当图层放进同一条时间线。
2. **机位对齐**：实拍要用固定机位。已知产品尺寸，在实拍帧里标出几个角点，就能反算相机的位置和焦距，让 CG 产品和实拍产品对上，然后无缝替换。镜头一动就要做逐帧的相机跟踪，工作量大很多。
3. **实拍替换 CG 场景**：比如用真实房间当背景，把面积框、读数面板叠上去，比 CG 房间更可信。

注意帧率要一致（25、30、60fps），以及 CG 和实拍的色温、颗粒、景深差异，衔接点用淡化或光晕转场来藏。以上三档在本流程里还没有实际做过，第一次做时先拿一个镜头试。

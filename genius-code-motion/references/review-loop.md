# 抽帧检查与排查

## 批量抽帧

在 Remotion 项目根目录运行（`<skill>` 换成本技能目录）：

macOS / Linux：

```bash
node '<skill>/scripts/stills.mjs' --comp Main --out out/stills --frames 0,60,120-300:60 --sheet 3
```

Windows PowerShell：

```powershell
node '<skill>\scripts\stills.mjs' --comp Main --out out\stills --frames 0,60,120-300:60 --sheet 3
```

- `--frames` 支持单帧和范围，`120-300:60` 表示从 120 到 300、每隔 60 帧取一帧。
- `--sheet 3` 表示把所有帧拼成每行 3 张的对照图 `sheet.jpg`，需要本机有 ffmpeg。
- `--html` 生成带帧号和时间码的图册页 `index.html`，交给用户做静帧分镜确认、或按「第几秒」反馈。
- `--props props/nosub.json` 用和渲染命令一样的参数出图，比如检查无字幕版、分层版。
- 一次打包、一个浏览器连续出图，十几张通常只要几秒到几十秒。
- 渲染报错时加 `--verbose`，能看到浏览器控制台的输出。

## 取哪些帧

- 每个镜头的开头、中段、结尾各取一帧；
- 每个转场的中点；
- 有数字变化的地方（计数、读数）取关键值出现的那一帧；
- 改了哪段就重点抽哪段，最后出片前再全片按固定间隔抽一遍。

## 逐镜检查清单

- **连续性**：相邻镜头之间亮度、色调不能突然跳变。
- **遮挡**：标注、面板、字幕不能互相压住，也不能压住主体。
- **可读性**：小字在 1080p 下能看清；浅色字放在亮背景上要加阴影或底板。
- **数据一致**：画面上的计数、读数和 3D 状态一致，算式结果正确。
- **结构正确**：数量、排布和确认过的建模清单一致。
- **穿帮**：画面边缘有没有露出场景边界、虚空、飘在空中的部件。
- **发光**：发光体有没有变成实心色块，辉光有没有过曝吞掉细节。

## 问题排查顺序

| 现象 | 先查什么 |
|---|---|
| 3D 层全黑，叠加层正常 | 关掉后期看 3D 能不能出图；能出图就是后期管线的问题（见 `postprocessing.md`） |
| 某段部件消失、发光体变暗 | 深度精度：近裁剪面太小、两层面贴得太近。近裁剪面要随距离变化，层间留足间距，加 `polygonOffset` |
| 画面突然变亮或变暗 | 灯光入射角随镜头变化；按「照度 × 距离²」算强度，再在这一段单独补偿 |
| 只有某一帧异常 | 把那一帧的状态函数值打出来看，通常是关键帧或包络的边界写错了 |
| 标注偏离部件 | 标注和 3D 是不是用了同一个 `getCam`；锚点有没有算上拆解时的偏移 |
| 第一帧特别慢 | 正常，第一次要下载无头 Chrome |
| 动画一顿一顿、一格一格 | 按下面「流畅度检查」量化：走走停停是分段缓动，一格一格是每帧位移太大 |
| 某一刻突然炸光、过曝一两帧 | 有灯离发光面太近且线性亮起；强度改成 `t³` 慢起，或把灯移远 |
| 某几颗透镜、发光体整颗不见，换个角度又出来 | 透明贴片（高清补丁、印刷层）后画、盖掉了先画的加法发光；贴片设更小的 `renderOrder` |
| 透镜像一层奶白色的皮 | 用了低不透明度的白色材质；改 `transmission`，见 `look-dev.md` 的透明透镜配方 |

排查时一次只改一个变量。

## 流畅度检查

用户说「卡」时，两种量法都做，改完再量一次对比。

**1. 逐帧画面差（量渲出来的片子）**：相邻两帧相减取平均亮度，看哪几帧突然变大（跳变）或在运镜中途掉到接近 0（停顿）。

```bash
ffmpeg -i out/draft.mp4 -vf "scale=480:-1,tblend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=diff.txt" -f null -
```

`diff.txt` 里每帧一个 `YAVG`。某帧比前一帧大好几倍就是突跳，去看那一帧前后的画面；运镜过程中数值反复「高—低—高」就是走走停停。注意灯珠点亮、闪光这类内容变化也会让数值变大，要对照画面区分。

**2. 逐帧相机像素位移（不用渲染，直接算相机函数）**：在屏幕上取一个 5×5 网格，每帧把网格点按对焦距离投到 3D 里，再用下一帧的相机投回屏幕，算平均像素位移。得到每帧镜头在屏幕上移动了多少像素。

- 项目源码是 TS，用项目自带的 esbuild 打包成脚本再用 node 跑，`NODE_PATH` 指向项目的 `node_modules` 才能解析 `three`：
  `NODE_PATH="$PWD/node_modules" node_modules/.bin/esbuild probe.ts --bundle --platform=node --format=esm --outfile=probe.mjs && node probe.mjs`
- **判读**：看三样——峰值（每帧最多移动多少像素）、相邻帧速度变化的最大值（有没有急刹急加速）、运镜中途有没有掉到接近 0 的点。30fps、没有运动模糊时，峰值到几十像素就会有一格一格的感觉，越低越顺；相邻帧速度变化应该是平缓的小数。

**常见原因和改法**

| 量出来的样子 | 原因 | 改法 |
|---|---|---|
| 运镜中途在关键点附近速度掉到接近 0 再加速 | 用 `keys()` 分段缓动，每段各自慢起慢停 | 整段只用一条缓动 `u`，各参数用 `spline()` 挂在 `u` 上 |
| 某一小段峰值特别高 | 大部分拉远量挤在这一小段（比如对数距离在几帧里跨了一个数量级） | 拉远量按对数距离均匀铺开；横移放到镜头慢下来的段落 |
| 几个参数各自在不同帧变速，速度曲线有折角 | 距离、横移、转角各有一套关键帧时间 | 所有参数都按同一个 `u` 取值，而不是各自按帧号 |
| 整体都偏快 | 时长不够 | 和用户商量整体拉长，见 `architecture.md` 的「多版本共用建模」里的整片改时长 |

流畅度改完给用户看半分辨率小样，静帧看不出流畅度。同一个问题连续改两次都没好，就停下来重新找根因，不要继续猜。

## 给用户审片

1. **静帧分镜**：分镜确认关交图册页（`--html`），见 `storyboard.md`。
2. **小样**：动画做完先出半分辨率小样（`npm run draft`），带配音，用户审节奏和内容。
3. **成片**：小样定了再出正式成片和用户要的分层版本。

每一轮都让用户按「第几秒」或「第几镜」反馈，改完只重渲受影响的部分做抽查。

## 出片核对

- 用 `ffprobe` 核对时长、分辨率、帧率、总帧数；有配音的版本要有音轨，透明叠加层的像素格式要带 alpha；
- 用 ffmpeg 按固定间隔抽帧拼一张总览图，从头到尾看一遍；
- 交付时说清：检查过哪些帧，哪些没验证（比如还没对配音节奏）。

# 抽帧检查与排查

## 批量抽帧

在 Remotion 项目根目录运行（`<skill>` 换成本技能目录）：

macOS / Linux：

```bash
node '<skill>/scripts/stills.mjs' --comp Main --out out/stills --frames 0,60,120-300:60 --sheet 3
```

Windows PowerShell：

```powershell
node '<skill>\scripts\stills.mjs' --comp Main --out out\stills --frames 0,60,120-300:60 --sheet 3
```

- `--frames` 支持单帧和范围，`120-300:60` 表示从 120 到 300、每隔 60 帧取一帧。
- `--sheet 3` 表示把所有帧拼成每行 3 张的对照图 `sheet.jpg`，需要本机有 ffmpeg。
- `--html` 生成带帧号和时间码的图册页 `index.html`，交给用户做静帧分镜确认、或按「第几秒」反馈。
- `--props props/nosub.json` 用和渲染命令一样的参数出图，比如检查无字幕版、分层版。
- 一次打包、一个浏览器连续出图，十几张通常只要几秒到几十秒。
- 渲染报错时加 `--verbose`，能看到浏览器控制台的输出。

## 取哪些帧

- 每个镜头的开头、中段、结尾各取一帧；
- 每个转场的中点；
- 有数字变化的地方（计数、读数）取关键值出现的那一帧；
- 改了哪段就重点抽哪段，最后出片前再全片按固定间隔抽一遍。

## 逐镜检查清单

- **连续性**：相邻镜头之间亮度、色调不能突然跳变。
- **遮挡**：标注、面板、字幕不能互相压住，也不能压住主体。
- **可读性**：小字在 1080p 下能看清；浅色字放在亮背景上要加阴影或底板。
- **数据一致**：画面上的计数、读数和 3D 状态一致，算式结果正确。
- **结构正确**：数量、排布和确认过的建模清单一致。
- **穿帮**：画面边缘有没有露出场景边界、虚空、飘在空中的部件。
- **发光**：发光体有没有变成实心色块，辉光有没有过曝吞掉细节。

## 问题排查顺序

| 现象 | 先查什么 |
|---|---|
| 3D 层全黑，叠加层正常 | 关掉后期看 3D 能不能出图；能出图就是后期管线的问题（见 `postprocessing.md`） |
| 某段部件消失、发光体变暗 | 深度精度：近裁剪面太小、两层面贴得太近。近裁剪面要随距离变化，层间留足间距，加 `polygonOffset` |
| 画面突然变亮或变暗 | 灯光入射角随镜头变化；按「照度 × 距离²」算强度，再在这一段单独补偿 |
| 只有某一帧异常 | 把那一帧的状态函数值打出来看，通常是关键帧或包络的边界写错了 |
| 标注偏离部件 | 标注和 3D 是不是用了同一个 `getCam`；锚点有没有算上拆解时的偏移 |
| 第一帧特别慢 | 正常，第一次要下载无头 Chrome |

排查时一次只改一个变量。同一个问题连续改两次都没好，就停下来重新找根因，不要继续猜。

## 给用户审片

1. **静帧分镜**：分镜确认关交图册页（`--html`），见 `storyboard.md`。
2. **小样**：动画做完先出半分辨率小样（`npm run draft`），带配音，用户审节奏和内容。
3. **成片**：小样定了再出正式成片和用户要的分层版本。

每一轮都让用户按「第几秒」或「第几镜」反馈，改完只重渲受影响的部分做抽查。

## 出片核对

- 用 `ffprobe` 核对时长、分辨率、帧率、总帧数；有配音的版本要有音轨，透明叠加层的像素格式要带 alpha；
- 用 ffmpeg 按固定间隔抽帧拼一张总览图，从头到尾看一遍；
- 交付时说清：检查过哪些帧，哪些没验证（比如还没对配音节奏）。
